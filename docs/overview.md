# Обзор проекта

## Проблема

Сотрудники тратят время на ручной поиск ответов в регламентах, должностных инструкциях и FAQ.
«Простой» LLM-чат не знает внутренних документов и **галлюцинирует**: уверенно выдаёт
правдоподобные, но выдуманные ответы на вопросы о локальных правилах организации.

## Решение

RAG (Retrieval-Augmented Generation): ответ строится **только** из найденных фрагментов базы
документов, каждый ответ сопровождается ссылкой на источник `[документ, фрагмент]`.
Если релевантных фрагментов нет (score ниже порога) — вежливый отказ «Нет в документах».

## Цель проекта

Разработать Streamlit-чат-бота на базе RAG, отвечающего на вопросы сотрудника только по
загруженной базе документов, с указанием источников и корректным отказом, если ответа в базе нет.

## Пользователь

Сотрудник организации без технической подготовки: задаёт вопрос обычным языком, получает
краткий ответ со ссылкой на документ и пункт.

## Данные

- Стартовый корпус: **50–100 документов** (PDF / DOCX / MD) — устав, регламенты,
  должностные инструкции, FAQ.
- Источник: синтетический корпус организации + открытые регламенты.
- Только текстовый (born-digital) корпус: **сканы и изображения на старте исключены** (см. ограничения).
- Ожидаемый объём: ~150–250 тыс. токенов → ~500–1500 чанков (зависит от размера чанка).

## Функциональные требования

1. **Чат**: потоковый ответ, история диалога в сессии, отображение источников (документ,
   фрагмент, score) под каждым ответом.
2. **Отказ**: при score < порога — «Нет в документах» вместо генерации.
3. **Админка**: загрузка документов (PDF/DOCX/MD), список документов со статусом индексации,
   удаление/переиндексация, настройка `top_k` и порога отказа без перезапуска.
4. **Индексация**: офлайн-конвейер парсинг → очистка → структурный чанкинг → эмбеддинги →
   векторное хранилище; повторный запуск идемпотентен (по хэшу файла).
5. **Оценка качества**: воспроизводимый eval-скрипт (метрики + таблица сравнения с baseline).

## Нефункциональные требования

| Требование | Значение |
|---|---|
| Latency ответа (p50) | ≤ 5 с на GPU (7B), ≤ 10–15 с на CPU (3B) |
| Воспроизводимость | зафиксированные версии моделей, `seed`, сохранённый индекс, temp генерации ≤ 0.2 |
| Запуск | `docker compose up` или 3 команды из [launch.md](launch.md) |
| Изоляция данных | модели локальные (Ollama), документы не покидают машину; внешний API — только опционально |

## Ограничения (честно заявлены)

- Отвечает **только** по базе: вопрос вне базы → отказ, без «общих знаний».
- Таблицы и сканы — только после OCR; изображения не понимаются (OCR вне объёма на старте).
- Качество зависит от полноты корпуса и чанкинга.
- Итоговый ответ ограничен окном контекста LLM (релевантные чанки + ответ ≤ ~2 тыс. токенов).

## Метрики успеха (кратко)

- Ретривер: **Hit@5 ≥ 0.85**, MRR@5 ≥ 0.5 на QA-наборе.
- Генерация: **Faithfulness ≥ 0.8**, Answer Relevancy ≥ 0.75.
- Отказы: корректные отказы ≥ 0.8, ложные отказы ≤ 0.15.
- Превосходство над baseline (Qwen без RAG) по доле правильных ответов и доле галлюцинаций.

Полный протокол и обоснование порогов — в [evaluation.md](evaluation.md).
