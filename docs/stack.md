## 1. Модель эмбеддингов (главный выбор проекта)

### Основная: `intfloat/multilingual-e5-base`

| Параметр | Значение |
|---|---|
| Размерность | 768 |
| Окно внимания | **512 токенов** — соответствует чанку ~500 токенов из ТЗ |
| Языки | мультиязычная, включая русский (обучена на mC4/XLMR, проверена на MIRACL, Mr.TyDi) |
| Параметры | ~278M — эмбеддинг ~2000 чанков на CPU за минуты |
| Лицензия | MIT |
| Особенность | обязательные префиксы: `"query: "` для запроса, `"passage: "` для чанков |

**Почему именно она:**
- Соответствует требованию ТЗ «чанкинг ~500 токенов»: окно 512, значит чанк попадает
  в модель целиком (с учётом префикса и CLS/SEP — цель до ~500).
- Мультиязычность критична: корпус на русском, а англоцентричные MiniLM дают заметно
  слабее retrieval на русском.
- Достаточно лёгкая для CPU-only окружения, но заметно качественнее MiniLM на Retrieval.

### Fallback (light): `sentence-transformers/multilingual-MiniLM-L12-v2`

- 384-dim, 12 слоёв, ~118M параметров, лицензия MIT, работает на CPU быстрее всех.
- **Критическое ограничение:** `max_seq_length = 128` токенов. При чанке 500 токенов
  вторая часть чанка **молча отбрасывается** — индексируется только начало, recall падает.
  Поэтому при выборе этой модели:
  - либо уменьшить чанк до ~120 токенов (`chunking.size_tokens: 120`, overlap 20),
  - либо поднять `max_seq_length` до 512 с осознанным падением качества
    (модель обучалась на длинах ≤128).
- Применение: режим `embedding=light` для быстрой разработки/CI или слабых машин.
  Сравнение моделей на своём корпусе — обязательный пункт отчёта.

### Активная конфигурация: бэкенд Ollama (`qwen3-embedding:0.6b`)

В рабочей среде этого проекта CDN Hugging Face (`us.aws.cdn.hf.co`) недоступен —
скачивание весов обрывается на TLS-хендшейке (проверено: Python/curl/зеркало
`hf-mirror.com` — веса всё равно редиректятся на оригинальный CDN). Поэтому
активен второй бэкенд эмбеддингов, объединённый с LLM-стеком (Ollama уже
требуется для генерации):

| Параметр | Значение |
|---|---|
| Модель | `qwen3-embedding:0.6b` (Ollama, Qwen3-Embedding-0.6B) |
| Размерность | 1024 |
| Окно внимания | 32K токенов — чанк 500 токенов целиком без усечения |
| Языки | мультиязычная, сильный русский (новее e5, MTEB-лидер) |
| Размер | ~640 MB, API: `POST /api/embed`, токенизатор: `POST /api/tokenize` |
| Префиксы | не требуются |

Переключение — одна строка в `config.yaml`:

```yaml
models:
  embedding_backend: ollama              # или sentence_transformers
  embedding: qwen3-embedding:0.6b        # либо intfloat/multilingual-e5-base
```

Абстракция (`src/embedder.py`: `create_embedder`) едина для обоих бэкендов:
`encode_passages / encode_query / count_tokens / dim`. **Смена модели
обязательно требует полной переиндексации** (`python -m src.ingest --force`) —
иначе размерности векторов не совпадут (ошибка подскажет команду).

### Отвергнуто (и почему)

| Вариант | Причина отказа |
|---|---|
| `all-MiniLM-L6-v2` / `all-MiniLM-L12-v2` | англоцентричные → слабый русский retrieval |
| `multilingual-e5-large` | +качество, но ~4× медленнее на CPU без заметного выигрыша на 500–1500 чанках |
| `bge-m3` | отличная модель, но для корпуса в 100 документов избыточна по размеру; допустима как эксперимент |

## 2. Генеративная модель

### Основная: `Qwen2.5-7B-Instruct` (Ollama: `qwen2.5:7b`)

| Параметр | Значение |
|---|---|
| Параметры | 7.4B, архитектура transformer, гибридный K/V cache |
| Квантизация | Q4_K_M (~4.7 GB весов) → реально ~5–6 GB RAM/VRAM с контекстом |
| Окно контекста | 32K токенов (для RAG нужно ~2–4K: чанки + ответ) |
| Русский язык | сильный (обучение на 100+ языков, инструктинг) |
| Лицензия | Qwen License (свободная для research/commercial) |
| Режим запуска | локально через **Ollama** (`ollama serve`), HTTP API на `:11434` |

**Почему она:**
- Локальный запуск → документы не покидают машину (важно для внутренних регламентов).
- 7B — компромисс: уверенно следует промпту «отвечай только по контексту», даёт связные
  ответы с цитатами, помещается в 8 GB VRAM / 16 GB RAM.
- Инструктинг и стабильный формат ответа (без «рассуждений» в тексте) — проще парсить
  ссылки и детерминировать вывод (temperature 0.2).

### Варианты запуска

1. **Ollama (основной)**: `ollama pull qwen2.5:7b`; endpoint из `.env`.
2. **CPU-only fallback**: `qwen2.5:3b-instruct` — быстрее на CPU, качество ниже;
   включается одной строкой конфига (`models.llm: qwen2.5:3b`).
3. **API fallback**: любой OpenAI-совместимый endpoint (DashScope Qwen, OpenRouter)
   — для машин без ресурсов; включается `models.llm_endpoint`.
4. **Апгрейд (опция)**: `qwen3:8b` (гибридный thinking-режим) — сравнить на eval-наборе
   перед финальной защитой; в thinking-режиме обязателен разбор `<think>`-блока.

### Модель-судья (LLM-as-judge)

- По умолчанию — **та же `Qwen2.5-7B-Instruct`** для Faithfulness / Answer Relevancy
  (дешёво, локально). Оговорка в отчёте: self-preference bias судьи.
- При доступном API — судья на более сильной модели (`qwen-plus` / `gpt-4o-mini`),
  результаты сравниваются на подмножестве.

## 3. Хранилище: замена PostgreSQL + pgvector → ChromaDB

| Критерий | pgvector | **ChromaDB** |
|---|---|---|
| Что поднимать | отдельный сервер, диск, миграции | встраивается в процесс приложения |
| Объём данных | избыточно (несколько МБ векторов) | достаточно |
| cosine-поиск | да | да (`space="cosine"`) |
| Фильтры по метаданным | SQL | встроенные (`where={...}`) |
| Персистентность | да | да (`PersistentClient("data/chroma")`) |
| Точки отказа на демо | больше | меньше |
| Порог передачи на защиту | риск с инфраструктурой | `streamlit run app.py` |

Реестр документов (статусы, хэши) — **SQLite** из стандартной библиотеки: без ORM и
сервера. При переходе на серверный режим миграция на pgvector тривиальна
(таблицы `documents(id, name, meta)` / `chunks(id, doc_id, text, embedding)`).

Отклонены также: FAISS (нет готовой персистентности и метаданных), LanceDB (тяжелее
нужного), «numpy-массив в файле» (нет фильтров и транзакций).

## 5. Аппаратные требования

| Режим | Конфигурация | Ожидаемая latency (p50) |
|---|---|---|
| GPU (рекомендуется) | 8 GB VRAM, 16 GB RAM | ≤ 5 с |
| CPU-only, 7B | 16 GB RAM (Ollama на CPU) | 15–30 с |
| CPU-only, 3B | 8 GB RAM | 10–15 с |

Индексация (единоразово): `qwen3-embedding:0.6b` на CPU — child-фрагменты
демо-корпуса (~40 шт.) индексируются за секунды; ~2000 фрагментов — минуты.
